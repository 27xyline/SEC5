# SEC5 — проверка заголовков C++

Утилита читает один исходный файл, извлекает имена заголовков из директив
`#include` и сравнивает их с разрешённым списком. Проект использует C++17,
CMake и GoogleTest.

## Сборка и тесты

Из корня проекта выполните:

```sh
cmake -S . -B build
cmake --build build
(cd build && ctest --output-on-failure)
```

Для сборки нужны CMake 3.16 или новее и компилятор C++17. CMake ищет
установленный GoogleTest. Если его нет, при первой настройке он скачивает
исходники GoogleTest с GitHub. Для сборки одной утилиты без загрузки
GoogleTest передайте `-DBUILD_TESTING=OFF` первой команде.

## Запуск

```sh
./build/sec5 list examples/sample.cpp
./build/sec5 check examples/sample.cpp examples/allowed.txt
```

Первая команда печатает уникальные имена заголовков в порядке первого
появления. Для записи списка в файл используйте перенаправление вывода:

```sh
./build/sec5 list examples/sample.cpp > headers.txt
```

Формат списка разрешений — одно имя на строку без кавычек и угловых
скобок. Например, `iostream` и `lib/config.hpp` записываются на разных
строках. Пробелы по краям и пустые строки игнорируются. Имена сравниваются
с учётом регистра. `<x.hpp>` и `"x.hpp"` дают одно имя `x.hpp`.

В примере разрешён только `iostream`, поэтому `check` выводит:

```text
examples/sample.cpp:2: header not allowed: debug.hpp
```

Код завершения `0` означает успешную работу, `1` — найдены заголовки вне
списка, `2` — неправильная команда или ошибка чтения файла. В режиме
`check` выводится каждое нарушение, даже если имя уже встречалось.

## Как работает код

1. **`src/main.cpp`** проверяет аргументы командной строки и открывает
   входные файлы. Он вызывает функции из `sec5_core` и форматирует вывод.
2. **`src/includes.hpp`** описывает структуру `Include`. В ней хранятся имя
   заголовка и номер строки. Тип `AllowedHeaders` — хеш-множество строк.
3. **`readIncludes`** в `src/includes.cpp` читает строки через
   `std::getline` и увеличивает счётчик строк. Функция `withoutComments`
   обрабатывает комментарии перед поиском директивы. Флаг `inBlockComment`
   хранится между итерациями, поэтому строки внутри многострочного
   комментария пропускаются. Комментарий заменяется пробелом, чтобы
   части слова по обе стороны комментария случайно не склеились.
4. **Регулярное выражение** ищет директиву в начале очищенной строки.
   `\s*` допускает пробелы до и после `#` и перед именем. Одна группа
   извлекает текст между `<` и `>`, другая — между кавычками. В результате
   остаётся само имя заголовка. Например, из `# include "lib/config.hpp"`
   получится `lib/config.hpp`.
5. **`readAllowedHeaders`** убирает пробелы по краям строк и складывает
   имена в `std::unordered_set`. **`findForbidden`** проходит по найденным
   директивам и оставляет те, для которых `allowed.count(name) == 0`.
6. **`tests/includes_test.cpp`** проверяет функции на потоках
   `std::istringstream`. Это позволяет передать текст прямо из теста.
   На Unix CTest также запускает проверку команд и кодов завершения
   из `tests/check_cli.sh`.

## Границы разбора

Это текстовый анализ одного файла. Он учитывает обычные однострочные
директивы с буквальным именем заголовка. Директивы внутри веток
`#if`, включая `#if 0`, учитываются по их наличию в тексте.
Раскрытие макросов, продолжение строк через обратную косую черту,
многострочные raw-строки и обход вложенных заголовков выходят за рамки
реализованного разбора.
